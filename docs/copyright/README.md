# 软著申请材料生成器

按中国版权保护中心的要求，用仓库里的代码自动生成软著材料。

依据（官方原文）：[中国版权保护中心 · 所需文件](https://www.ccopyright.com/index.php?optionid=1080)

> 程序和文档的鉴别材料应当由源程序和任何一种文档前、后各连续 30 页组成。
> 整个程序和文档不到 60 页的，应当提交整个源程序和文档。
> **除特定情况外，程序每页不少于 50 行，文档每页不少于 30 行。**

## 为什么用脚本而不是手排

三条硬要求手工排版几乎必错：

| 要求 | 手工排版的坑 |
|---|---|
| 程序每页 ≥50 行 | 一条长代码折行，这页就装不下 50 行，页数跟着变 |
| 前 30 页 + 后 30 页共 60 页 | 手数容易错，且删改后要重数 |
| **文档每页 ≥30 行** | 截图一放就挤掉文字，行数不达标 |
| 三份材料的软件名称与版本号逐字一致 | 改一处忘一处，直接被要求补正 |

## 用法

`ash
python docs/copyright/gen-source-and-manual.py      # 源程序 + 说明书
python docs/copyright/gen-form-and-checklist.py     # 申请表填写内容 + 材料清单
`

改软件名称或版本号：两份脚本顶部的 SOFTWARE_FULL / SOFTWARE_VERSION 要一起改。

## 踩过的坑（改脚本前必看）

1. **必须排除第三方库**。uni-app/libs/three/* 与 static/draco/* 是他人代码
   （35,000+ 行），混进源程序会被认定"含他人已登记代码"。
2. **.md 文档不能当源码收进去**。中文长句折行，撑破 50 行/页。
3. **图片段落必须单独设单倍行距**。Normal 是固定行距，Word 会把内嵌图片
   **裁到一行高**（表现：21 页说明书被压成 4 页）。且设完
   line_spacing_rule = SINGLE 后**不能再写** line_spacing = None，
   那句会把刚设的规则清掉。
4. **文档每页 ≥30 行是最难的一条**。手机截图高宽比约 1:2.2，一张图占约 20 行版面；
   19 张图就把每页文字压到 16 行。换算关系是：
   文字行数 ≥ 图片张数 × 每张占行数，否则页数变多而每页行数达不到 30。
   最终方案：图缩到 3.6cm 内联、只留 6 张、正文按操作步骤写厚。
5. **页数必须实测**：Word Repaginate() 后 ComputeStatistics(2)，
   不能靠算行数或 PDF 文本抽取（空行与图片会导致抽取失真）。
6. **不要加"此处省略"说明行**：1 行说明会把 3000 行顶成 3001 行、页数变 61。
