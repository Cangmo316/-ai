# 软著申请材料生成器

按中国版权保护中心的要求，用仓库里的代码自动生成软著材料。

## 为什么用脚本而不是手排

三个格式要求是"硬"的，手工排版极易出错：

| 要求 | 手工排版的坑 |
|---|---|
| 源程序**每页不少于 50 行** | 一条长代码折行，这一页就装不下 50 行，页数跟着变 |
| 源程序**前 30 页 + 后 30 页**共 60 页 | 手数页数容易错，且删改后要重数 |
| 三份材料里**软件名称与版本号逐字一致** | 手改一处忘改另一处，直接被要求补正 |

脚本用固定行距 + 按 50 行强制分页保证版式，名称/版本号只在文件顶部定义一次。

## 用法

`ash
# 1. 生成源程序与说明书（产出 docx）
python docs/copyright/gen-source-and-manual.py

# 2. 生成申请表填写内容与材料清单
python docs/copyright/gen-form-and-checklist.py

# 3. 转 PDF（Word 必须已安装）
#    PowerShell: Word COM 导出，见提交说明；或直接在 Word 里另存为 PDF
`

改软件名称或版本号：只改脚本顶部的 SOFTWARE_FULL / SOFTWARE_VERSION，两处脚本都要改。

## 已经踩过的坑（改脚本前先看）

1. **必须排除第三方库**。uni-app/libs/three/* 与 static/draco/* 是他人代码
   （35,000+ 行），混进源程序会被认定"含他人已登记代码"。
2. **.md 文档不能当源码收进去**。中文长句会折行，撑破 50 行/页。
3. **图片段落必须单独设单倍行距**。Normal 样式是固定行距（为了让源程序正好
   50 行/页），Word 在固定行距下会把内嵌图片**裁到一行高** —— 表现是 21 页的
   说明书被压成 4 页。只设 line_spacing_rule = SINGLE，**不要**再写
   line_spacing = None（那句会把刚设的规则清掉）。
4. **tar/文件名里的页面数要实测**。脚本生成的 docx 需用 Word Repaginate() 后
   再 ComputeStatistics(2) 数页数，不能只靠算行数。
