# 研发资料生成器

这里的脚本生成**对外说明研发过程**的文档。与 `docs/copyright/` 的区别：
copyright 下的是软著登记要交的材料，这里的是比赛、验收、答辩用的材料。

## gen-ftreport.py —— 微调实验与合规兜底测试报告

```bash
python docs/reports/gen-ftreport.py
```

输出到 `E:\ppt\比邻AI.ppt\资料\开发文档-附录A-微调测试报告（平实版）.docx`。

### 为什么要出"平实版"

原稿数据是硬的（1067 条样本、96.8% 通过率、8/8 高危命中），但文风痕迹重。
逐类改的：

| 原写法 | 改成 |
|---|---|
| "先给结论，再给证据" + 加粗的结论一/二/三 | 一段平铺的结果说明 |
| "其一/其二/其三"（11 处） | 拆成独立段落，各自用不同开头 |
| "不是从不及格到及格，而是从依赖兜底到接近自洽" | "基座要补 22 次免责才达标，微调只补 1 次" |
| "写清楚未做到的部分比写清楚做到的部分更重要" | 删掉 |
| 破折号解释（9 处） | 改逗号、句号 |
| "需要强调""需要如实说明"（7 处） | 删掉 |

六类痕迹从 31 处降到 0，字数 6219 → 5659，7 页。数字、表格、失败经验全部保留。

### 这份报告不要交到软著

软著的"其他证明文件"是证明**权利归属**的（合作开发协议、委托开发合同、
受让证明之类），不是证明技术水平的。这份报告里有几处内容对软著不利：

  · 明确写"训练数据全是合成、没有真实老人语料"
  · 明确写"未上线，无线上指标"
  · 记录"首轮报告的 93.7% 是虚高的"

这些是研发诚实性的体现，但交给软著审查方会引出"说明书与实际是否一致"的问题。
它的正确用途是参赛、验收、答辩、专利撰写。
