三、✅ 已修完（用户实测反馈的两个 bug —— 2026-10-05 修复并提交 733194d）
================================================================================

■ Bug 1：mock 的音频只有 0.052 秒                        【已修复】
  现象：<audio> 实测 duration = 0.052125
  根因：我用"两帧静音 MP3"想造 1 秒，实际只解码出 52 毫秒
  我的错误：断言只检查"字节像 MP3"（帧同步字 0xFF 0xF?）→ **形状断言**，
            形状对、时长错，断言通过而功能是坏的
  改法：mock 改用运行时生成的 **3 秒静音 WAV**（时长可精确控制），
        durationMs 与字节数严格对应；Content-Type 如实改 audio/wav
  断言升级：从"像 MP3"改为"字节与声明格式一致 + 实际时长 ≥ 2 秒 + durationMs 对得上"

■ Bug 2：口型的时钟在音频就绪之前就起跑                   【已修复】
  现象：没看到唇形同步（嘴在音频出来之前已经演完）
  根因：播放器从 start() 起跑自有时钟，而音频要下载+解码（几百毫秒~几秒）
        → **两个时钟各自跑再想办法对齐**，这是设计错误
  改法：**单一时间源** —— clock: () => audio.currentTime * 1000
        （音频播到第几毫秒，嘴就摆到第几毫秒；不存在漂移，也不需要校准）
  配套：clock 返回 null 时退回自有时钟（不是当作 0，否则嘴卡句首）；
        口型立刻挂上不等 onPlay（不漏开头）；删掉 resync 轮询；
        stats().clockSource 如实报 'audio' | 'self'

■ 行为验证（这次是**行为断言**，不是形状断言）           【已通过】
  · 音频时长                      3.0 秒 ✓
  · 嘴真的动了                    167 / 326 个采样点有非零 viseme 权重 ✓

六、已知的"验证教训"（写下来避免重犯）
================================================================================
1. **形状断言 ≠ 行为断言**
   "字节像 MP3" 通过了，但音频只有 52ms —— 形状对、时长错。
   以后对音频要断言 duration；对 3D 要断言形态键权重，而不是"收到了数据"。
2. **数据到达 ≠ 功能生效**
   "音频 URL 到了端侧" 不代表"响了"；"cues 收到了" 不代表"嘴动了"。
3. **两个时钟各自跑必然漂移**
   音画同步只有一个正确做法：**单一时间源**（音频播到哪，嘴到哪）。
4. **同名替换资产必须破缓存**
   已踩两次（旧模型显示为企鹅/旧形象）。ASSET_VERSION 是硬性流程。
5. **换资产时"写死别的角色坐标"会静默出错**
   已参数化的坑：骨骼锚点、减面保护带、唇部掩膜、权重场、张嘴方向、招手轴、取景。
