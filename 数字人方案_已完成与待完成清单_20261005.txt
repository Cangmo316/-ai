■ ⚠️ 先纠正上一版（733194d）的错误结论：它只修掉了两条**表层** bug
  上一版在这里写了"听得到 + 看得见，已用行为断言验证通过" —— **这个结论是错的**。
  它落在两个没人断言的空档上（两次都是断言写不到，而不是代码想不到）：
    · mock 换成了 3 秒 WAV，**时长**断言确实过了，但负载**全 0 = 真静音** ——
      "没声音"与"播放链路坏了"在观感上分不开，而验收没断言"非静音"。
    · 端侧 H5 用的是 uni.createInnerAudioContext()，它的 play() 把内部
      <audio>.play() 的 Promise **直接丢掉**；而"自动播放被拦 / 解码失败 / 源不可达"
      正是靠这个 Promise 上报。丢掉后既不触发 onError 也没有日志 →
      "点了没声音，也不知道为什么"。
      同一条 URL 的对照实测：原生 new Audio() 能 resolve、currentTime 正常推进；
      uni 的内部元素停在 readyState=0 / networkState=3(NETWORK_NO_SOURCE)，连源都没选上。
      currentTime 恒为 0 → 口型读不到音频时钟 → **定格在句首**（"没唇形"）。

■ Bug 1：mock 的音频其实是**静音**的                        【已修复 b39bd25】
  现象：时长 3.000 秒、能解码、就是一点声音都没有（用户："没声音"）
  根因：buildSilentWav 的负载全 0；上一版把"时长"当成了判据，漏了"有没有声音"
  改法：buildSilentWav → buildToneWav（180Hz 基频 + 奇次谐波 ≈ 人声，
        叠 4 音节/秒的开口包络，峰值约 -8.7dBFS —— 听得见）
  断言升级：test:audio 新增**非静音**断言（PCM 峰值 ≥ 5% 满量程 + RMS ≥ 1%）

■ Bug 2：H5 的播放失败被 uni 封装**吞掉**                   【已修复 b39bd25】
  现象：点了"问一句"没声音，而且不知道为什么；口型定格在句首
  根因：uni H5 的 play() 丢掉了底层 <audio>.play() 的 Promise（见上）
  改法：H5 直接用原生 <audio>（包成端侧同一个小接口），**接住** play() 的 Promise：
        resolve → played=true；reject → 记 error，口型退回自有时钟把整句跑完。
        首次用户手势里用**同一个元素**播一帧静音 WAV 做解锁（移动端 Safari 的
        自动播放策略认的是"被播放过的那个元素"）；APP 端仍走 uni（#ifdef APP-PLUS）。
  诊断口子：window.__blVisionAudioState() 读**原生元素**状态
        （pos/paused/readyState/networkState/volume/mediaError）——
        旧验收读 uni 包装层，所以看不出静默失败。

■ Bug 3：口型时间轴比音频短一半（嘴先停、声音还在响）        【已修复 b39bd25】
  现象：嘴动 1.5 秒就回静止，而音频还要响 1.5 秒 → 看着仍然是"唇形不同步"
  根因：mock 音频固定 3 秒，而"按字数估算"的口型轴只有 1~2 秒
  改法：把估算时间轴**整体缩放**到音频时长（真后端靠 TTS 对齐天然同长）
  断言升级：test:audio 新增"口型关键帧盖到音频结束"+"lipsync durationMs ≈ audio"

■ 历史记录：上一轮（733194d）修掉的两条仍然有效
  · mock 音频从"两帧静音 MP3"（实测只有 0.052125 秒）改为 3 秒 WAV

六、已知的"验证教训"（写下来避免重犯）
================================================================================
1. **形状断言 ≠ 行为断言**
   "字节像 MP3" 通过了，但音频只有 52ms —— 形状对、时长错。
   以后对音频要断言 duration；对 3D 要断言形态键权重，而不是"收到了数据"。
2. **数据到达 ≠ 功能生效**
   "音频 URL 到了端侧" 不代表"响了"；"cues 收到了" 不代表"嘴动了"。
3. **两个时钟各自跑必然漂移**
   音画同步只有一个正确做法：**单一时间源**（音频播到哪，嘴到哪）。
4. **同名替换资产必须破缓存**
   已踩两次（旧模型显示为企鹅/旧形象）。ASSET_VERSION 是硬性流程。
5. **换资产时"写死别的角色坐标"会静默出错**
   已参数化的坑：骨骼锚点、减面保护带、唇部掩膜、权重场、张嘴方向、招手轴、取景。
6. **时长对 ≠ 有声**
   "3 秒 WAV、能解码、durationMs 也对得上"依然可以是**全零静音**。
   音频要多断言一层：峰值 / RMS（非静音）。
7. **封装会把失败吞掉**
   uni 的 InnerAudioContext.play() 丢掉了底层 <audio>.play() 的 Promise，
   自动播放被拦 / 解码失败既不报错也无日志。诊断要读**原生元素**的状态
   （readyState / networkState / mediaError），别只读包装层的"看起来播了"。
8. **音画同长也是契约**
   口型时间轴必须盖到音频结束；否则"嘴先停、声音还在响"，用户眼里就是"唇形不同步"。

■ ① 真语音：先把「声音是怎么来的」讲清楚
   H5 默认对接的是 **mock**（uni-app/api/config.js 的 DEFAULT_BASE_URL = http://127.0.0.1:8787），
   所以「没有具体的声音」= 当时 mock 出的是 3 秒**蜂鸣音**（buildToneWav），不是人说话。
   原来要加 --tts 才出人声 —— 太容易踩空，已改成**命令行默认就出真语音**：
     · `node tools/mock-server.mjs`            → 真人语音（本机离线合成）
     · `node tools/mock-server.mjs --no-tts`   → 回到蜂鸣音兜底（或显式 BILIN_MOCK_TTS=0）
   合成器：本机 Windows SAPI5（Microsoft Huihui Desktop - Chinese (Simplified)），离线、免费。
   · **为什么只有 CLI 默认开**：测试都是 `import { startMockServer }` 起 mock（tools/test-*.mjs 共 9 处），
     根本不走 CLI 分支；而 CI 机器没有中文声部，绝不能让测试去 spawn 声部把 CI 拖慢搞脆。
   · 合成失败**静默回落蜂鸣音**（每个原因只告警一次）——语音是锦上添花，绝不能拖垮对话链路。
   · 实测（tools/test-audio-channel.mjs，默认启动）：音频**非静音**（峰值/RMS 达标）、
     时长与文本同量级（0.05~0.5 秒/字）、durationMs 与字节算出的时长一致、口型轴盖到音频结束，20 项全绿。
   · ⚠️ **真后端（:8000）不在此列**：server/.env 里没有 DASHSCOPE_API_KEY，也没有 BILIN_TTS_*，
     所以 build_tts_provider() 落到 NullTtsProvider —— **一点音频都不发**，口型退回估算版。

■ ③ 挥手太假：根因是**静息姿势**，不只是动画幅度
   交付件 GLB 静息是 **T-pose**（取景到胸口，两臂平举像稻草人）；自带 wave 片段也极小 ——
   用 GLB FK 复算：2.6 秒里上臂只摆 ±5°、腕 5°，**手部总位移约 1cm**。用户看到的"假"是这两条叠加。
   修法（uni-app/common/face-gl/face-three.js，仅运行时逻辑，**没动资产**）：
     · 静息姿势：量「肩→手」方向与竖直向下的夹角 ×0.85，按 0.72/0.28 分到肩/肘
     · 关键帧按「离基准多远」加权左移偏移：贴 T-pose 的帧吃满下垂、美术定的姿势保留，
       且 t=0/末帧 = 静息 → **起止无缝**（stopAnimation 后轮廓精确回到 75.0×93.5%）
     · 招手片段改为**程序化生成**（同名 'wave'）：抬臂 148°、手部抬高 127.2°、摆动 ±22°、
       腕 9°、3 个来回、2.34 秒；量不出轴时自动回落交付件 wave
     · 坑：骨名被 PropertyBinding.sanitizeNodeName 规范化（upperarm.R → upperarmR），
       还按原名取骨会**静默什么都不做**

■ ③ 抓到并修掉两条真 bug（"没声音 + 没唇形"在服务端的那两条真根因）
   甲、字表重复累积 → 口型错位（server/app/voice/qwen_tts.py）
       现象：百炼对同一句会多次投递"增量快照"（实测 7 7 10 13 16 段），
             原实现 words.extend(...) 累加 → 17 字回复拿到 69 段、时间轴非单调，
             端侧按时间取样会取到"上一遍"，口型就错位。
       修法：新增 _extract_sentence_index() + WordSnapshotCollector，按
             payload.output.sentence.index **覆盖**（同一句只保留最后一份快照），
             收尾按句子号排序拼接；无句子号时取最长快照兜底。
       附带：duration_ms 由 0 改为末字结束毫秒（实测 3520）。修后 16 段、时间单调。

   乙、音频事件从不发出 → 完全没声音（server/app/orchestration/service.py）
       真因：_last_audio_payload 是 _build_lipsync() **内部**合成 TTS 时才写入的，
             而 generate() 写成"先取 payload 再合成" → if audio_payload 恒假
             → **配了 TTS 也一个 audio 事件都不发**（端侧表现就是"没声音"）。
       修法：新增 _audio_then_lipsync(reply_text, assistant_id)（**先合成、后取音频**，
             顺序不可能再写反），generate() 改为调它。
       附带：_store_audio 的 format 由写死 "mp3" 改为跟实际扩展名
             （wav 路线原来会下发错误格式）。
