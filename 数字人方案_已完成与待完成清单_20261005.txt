三、✅ 已修完（用户两次反馈"没声音 + 没唇形同步" —— 提交 733194d，又 2026-10-06 修完 b39bd25）

■ ⚠️ 先纠正上一版（733194d）的错误结论：它只修掉了两条**表层** bug
  上一版在这里写了"听得到 + 看得见，已用行为断言验证通过" —— **这个结论是错的**。
  它落在两个没人断言的空档上（两次都是断言写不到，而不是代码想不到）：
    · mock 换成了 3 秒 WAV，**时长**断言确实过了，但负载**全 0 = 真静音** ——
      "没声音"与"播放链路坏了"在观感上分不开，而验收没断言"非静音"。
    · 端侧 H5 用的是 uni.createInnerAudioContext()，它的 play() 把内部
      <audio>.play() 的 Promise **直接丢掉**；而"自动播放被拦 / 解码失败 / 源不可达"
      正是靠这个 Promise 上报。丢掉后既不触发 onError 也没有日志 →
      "点了没声音，也不知道为什么"。
      同一条 URL 的对照实测：原生 new Audio() 能 resolve、currentTime 正常推进；
      uni 的内部元素停在 readyState=0 / networkState=3(NETWORK_NO_SOURCE)，连源都没选上。
      currentTime 恒为 0 → 口型读不到音频时钟 → **定格在句首**（"没唇形"）。

■ Bug 1：mock 的音频其实是**静音**的                        【已修复 b39bd25】
  现象：时长 3.000 秒、能解码、就是一点声音都没有（用户："没声音"）
  根因：buildSilentWav 的负载全 0；上一版把"时长"当成了判据，漏了"有没有声音"
  改法：buildSilentWav → buildToneWav（180Hz 基频 + 奇次谐波 ≈ 人声，
        叠 4 音节/秒的开口包络，峰值约 -8.7dBFS —— 听得见）
  断言升级：test:audio 新增**非静音**断言（PCM 峰值 ≥ 5% 满量程 + RMS ≥ 1%）

■ Bug 2：H5 的播放失败被 uni 封装**吞掉**                   【已修复 b39bd25】
  现象：点了"问一句"没声音，而且不知道为什么；口型定格在句首
  根因：uni H5 的 play() 丢掉了底层 <audio>.play() 的 Promise（见上）
  改法：H5 直接用原生 <audio>（包成端侧同一个小接口），**接住** play() 的 Promise：
        resolve → played=true；reject → 记 error，口型退回自有时钟把整句跑完。
        首次用户手势里用**同一个元素**播一帧静音 WAV 做解锁（移动端 Safari 的
        自动播放策略认的是"被播放过的那个元素"）；APP 端仍走 uni（#ifdef APP-PLUS）。
  诊断口子：window.__blVisionAudioState() 读**原生元素**状态
        （pos/paused/readyState/networkState/volume/mediaError）——
        旧验收读 uni 包装层，所以看不出静默失败。

■ Bug 3：口型时间轴比音频短一半（嘴先停、声音还在响）        【已修复 b39bd25】
  现象：嘴动 1.5 秒就回静止，而音频还要响 1.5 秒 → 看着仍然是"唇形不同步"
  根因：mock 音频固定 3 秒，而"按字数估算"的口型轴只有 1~2 秒
  改法：把估算时间轴**整体缩放**到音频时长（真后端靠 TTS 对齐天然同长）
  断言升级：test:audio 新增"口型关键帧盖到音频结束"+"lipsync durationMs ≈ audio"

■ 历史记录：上一轮（733194d）修掉的两条仍然有效
  · mock 音频从"两帧静音 MP3"（实测只有 0.052125 秒）改为 3 秒 WAV
    （当时断言只检查"字节像 MP3"就放过 —— 教训见 §六 1）
  · 口型改为**单一时间源**：clock: () => audio.currentTime * 1000
    （两个时钟各自跑必然漂移；clock 返回 null 时退回自有时钟，而不是当作 0）

六、已知的"验证教训"（写下来避免重犯）
================================================================================
1. **形状断言 ≠ 行为断言**
   "字节像 MP3" 通过了，但音频只有 52ms —— 形状对、时长错。
   以后对音频要断言 duration；对 3D 要断言形态键权重，而不是"收到了数据"。
2. **数据到达 ≠ 功能生效**
   "音频 URL 到了端侧" 不代表"响了"；"cues 收到了" 不代表"嘴动了"。
3. **两个时钟各自跑必然漂移**
   音画同步只有一个正确做法：**单一时间源**（音频播到哪，嘴到哪）。
4. **同名替换资产必须破缓存**
   已踩两次（旧模型显示为企鹅/旧形象）。ASSET_VERSION 是硬性流程。
5. **换资产时"写死别的角色坐标"会静默出错**
   已参数化的坑：骨骼锚点、减面保护带、唇部掩膜、权重场、张嘴方向、招手轴、取景。
6. **时长对 ≠ 有声**
   "3 秒 WAV、能解码、durationMs 也对得上"依然可以是**全零静音**。
   音频要多断言一层：峰值 / RMS（非静音）。
7. **封装会把失败吞掉**
   uni 的 InnerAudioContext.play() 丢掉了底层 <audio>.play() 的 Promise，
   自动播放被拦 / 解码失败既不报错也无日志。诊断要读**原生元素**的状态
   （readyState / networkState / mediaError），别只读包装层的"看起来播了"。
8. **音画同长也是契约**
   口型时间轴必须盖到音频结束；否则"嘴先停、声音还在响"，用户眼里就是"唇形不同步"。
