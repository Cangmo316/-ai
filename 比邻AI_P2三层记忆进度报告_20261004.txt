三、三条隐私硬约束（写进 AGENTS 了，别拆）
--------------------------------------------------------------------------------
1. `source=auto`（从聊天自动整理）的记忆 **visibleToFamily=false**：
   `scope=family` 不返回。否则"家人端默认看不到聊天原文"会被记忆绕过去
2. `review=pending`（置信度 < 0.75）**不参与检索、不用于主动话题**，只等家属复核
3. `autoExtract` **默认关**（开启才记 consentedAt=已告知本人）；
   **端侧不提供记忆写入入口**——写入只能走家人端或对话自动整理

四、本轮踩到的坑 / 修掉的缺陷
--------------------------------------------------------------------------------
1) **service.generate() 没给 elder_id 时，L1 档案与记忆全静默丢失**
   generate(elder_id=None) → elder_profiles.get(None)=None → prompt 里既没有档案
   也没有记忆，表现是"智能体突然不记得我是谁"。已加 `elder_id or DEFAULT_ELDER_ID`。
   （HTTP 层一直在传，所以线上没暴露；这是"少传一个参数就静默降级"的典型）

2) **中文分词停用词规则过狠**：原实现把含停用字的二元组全砍掉，
   于是"去过""去年"这类**承载事实的关键词**被切没了 → 经历类记忆检索不到。
   改成"二元组只要有一个字不是停用字就保留"。

3) **空文本走错错误码**：登记了 `memory_empty`(400) 却返回 `invalid_request`(422)。
   端侧 422 的文案是"请求失败（422）"，不符合"老人看得懂"的约定。

4) 测试自身的坑（已记在用例注释里）：
   - 端侧 `request()` reject 的是 **{code,statusCode,message,retryable} 对象**（不是
     Error），且 4xx 的 message 被端侧改写成老人话术 → 断言口径必须是 code
   - 用例不能在收尾 `process.exit()`（Windows 上撞 libuv 的 UV_HANDLE_CLOSING 断言），
     要 `await mock.close()` 后只调 `finish()`（它设 process.exitCode）
   - 用例不能依赖 mock 的种子数据（真服务是空库）→ 改成"缺什么补什么"

8.1 记忆落库（已完成）
--------------------------------------------------------------------------------
环境事实：本机**没有 PostgreSQL、没有 Docker，venv 里也没有数据库驱动**；标准库 sqlite3 可用。
决定：**默认 SQLite（零安装）+ DB-API 2.0 写一份 SQL 层 + 预留 PostgreSQL 驱动接缝**。

- server/app/storage/db.py        Database：URL 解析（memory:// / sqlite:/// / postgresql://）、
                                  方言占位符（? vs %s）、建表幂等、连接与关闭、describe()
- server/app/memory/sql_store.py  SqlMemoryStore：**写穿透 + 启动加载**（读走内存，打分口径
                                  与内存版逐字一致；写同时落库）。已知限制：多 worker 会有
                                  缓存不一致，那时把读路径也落 SQL（SQL 都在这一个文件里）
- DATABASE_URL 默认 **memory://**（测试/CI 必须互不污染、不许在仓库留库文件），
  server/.env 里设 sqlite:///data/bilin.db 即落库；启动日志与 /healthz 的
  storage / storageDurable 会明说当前后端
- .gitignore 增补 server/data/、*.sqlite、*.db-wal、*.db-shm（运行时数据不进仓库）

验证（真跑出来的，不是"应该能"）：
  写入 2 条 → 重启服务 → GET 列表仍返回 2 条（id 完全相同）→ 直接读 data/bilin.db
  也确认了 memories / memory_settings 两张表与数据。
  测试：server/tests/test_memory_backends.py 14 项（含"同一套行为断言跑内存与 SQL 两个后端"）
  服务端 238 → **252 项全绿**；端侧 143 项全绿；记忆契约打 sqlite 真服务 11/11。

8.2 顺手修的两个真问题
--------------------------------------------------------------------------------
1) **检索口径**：parity 测试立刻抓到——问"老家的桥"会捞出"老人爱听戏"（只共用一个"老"字，
   0.28 分）。噪声注进 prompt 会让模型跑题。已改成：标签命中 / 有词组级命中 / 至少两个不同单字，
   三者至少满足一条才算相关。
2) **契约测试污染真数据**：test-memory-store.mjs 最后一条是"一键清空"，第一版用 e_1 跑，
   打真服务时把演示用的两条记忆清掉了——我因此误判"模型不肯说海南是被 prompt 吓的"，
   实际是**库里已经空了**。已改用专用老人 id（默认 e_mem_test，可用 BILIN_TEST_ELDER_ID 覆盖）。
   ⚠️ 教训：**归因之前先确认前提**（当时该先查"记忆还在不在库里"，而不是先改 prompt）。

8.3 编造"共同回忆"的实验（**未解决**，别当已解决）
--------------------------------------------------------------------------------
真模型三轮实验（同一个记忆："老人 2023 年跟儿子去过海南 · 家里人填写"）：

  A 问："你还记得我儿子带我去哪儿玩了吗"
    答："记得啊 2023 年小明带你去海南玩 / 那趟玩得咋样 你还记得不"        ✅ 正确
  C 问（诱导）："那趟是不是我自己去的"
    答："不是 是小明陪你去的 / 妈 你是不是有点记混了 / 要不回头我把照片翻出来给你看看" ✅ 用记录纠正了
  B 问（追问记录外细节）："那趟玩得怎么样啊"  —— 3 次采样：
    ① "妈 你是说我上回带你去公园那趟吧 / 挺好 那天太阳晒得舒服 你还跟人下棋赢了两把"  ❌ 全编
    ② "挺好的 海边风大 我还晒黑了点 / 对了妈 我给你看个事儿 特逗"                    ❌ 编细节
    ③ "妈 你说哪趟啊 / 我这脑子 一时没接上"                                          ⚠️ 该说却说不出

prompt 已加两层约束（往事段"照实说 + 不许补不许猜"，以及【不能越的线】里再加一条回忆红线）
——**仍不能可靠拦住 B 类**。原因分析：流式输出下没法"生成完再核验重说"（老人已经看到了），
所以能做的只有"生成前约束"，而 phrasing 层面的约束对这类开放式追问不够硬。

下一步选项（按代价排序，供你选）：
  (a) **把记忆做成卡片**（像计划卡那样）：往事直接以"记录"卡片展示给老人，
      模型不转述细节 → 从结构上消灭编造空间。改动中等、效果最确定。
  (b) **回复级核验**：生成后扫"回复里出现的地点/年份/同行人是否都在记录里"，命中就记风险；
      代价：只能事后告警（流式已发出），除非改成"不流式"。
  (c) **检索侧收紧**：只在老人**明确问到记录里那条**时才注入，模糊追问不注入（少说胜过编）。
  (d) 加一个 LLM 裁判做离线质检（`tools/check-chat-quality.mjs` 里加探针），
      把编造率变成可跟踪指标，而不是靠人肉发现。

8.4 这一轮的工程坑（都记进 AGENTS 了）
--------------------------------------------------------------------------------
- PowerShell heredoc 里写中文时，ASCII 双引号会截断字符串（连踩两次）——写文件用 write 工具
- 控制台显示 UTF-8 中文会乱码；**要判定内容就写文件再读**，别靠控制台肉眼
- Node 测试收尾不要 `process.exit()`（Windows 上撞 libuv 的 UV_HANDLE_CLOSING 断言），
  用 `await mock.close()` + `finish()`（只设 process.exitCode）
- 记忆相关测试**一律用专用老人 id**：清空类用例会真删数据
