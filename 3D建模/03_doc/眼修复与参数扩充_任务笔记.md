## 1. 诊断结论（已量化，可复现）

测量脚本：`tools/blender-measure-eyes.py`（无头 Blender 运行）
判定标准：**眼裂开孔那一圈边界顶点到眼球球心的距离应当 ≈ 球半径 R（且 σ 小）**
—— 小于 R 说明眼皮扎进球里（穿模），大于 R 说明有缝（眼白过多/漏光），σ 大说明眼眶形状与眼球不匹配。

### 8.2 关键教训：锚点不能用"头部高度比例法"

原始网格的"头顶"含**头发体积**，比例法把整张脸算高 3~4cm
（实测算出嘴高 1.073 与眼高 1.070 齐平，明显错误）。
正确做法：**复用美术确认过的既有骨骼表**（`01_female_60s_v3/BilinAI_FaceRig_60k_edit.blend`）
——其包围盒与原始高模逐位一致（`0.6995/0.2333/1.1882`），同一坐标系，可直接当锚点：

```
neck (0,0.008,0.942) → head (0,0.005,0.998) → 头顶 1.112
jaw (0,0.012,1.062) → (0,-0.070,1.012)      chin 1.024
nose (0,-0.072,1.072) → (0,-0.087,1.049)    唇上/下 1.034 / 1.024
眉 1.093   上睑 1.086   下睑 1.056   颧骨 x=0.040 z=1.052   耳 (0.052,0.016,1.072)
★ 原眼位（掏空前 eye.L/R 顶点组形心）= (±0.0349, -0.0584, 1.0701)
  既有骨骼表里写的是 (±0.0239, -0.0549, 1.0712) —— 那是**上一轮放错 1cm 的球位**，不要用
```

## 8.6 【完成】v2 眼区：从"插球"改为"雕穹顶"（本轮最重要的技术结论）

### 8.6.1 先量准"眼位与眼裂"——雕塑的眼睛是**画在贴图上的**

用 `tools/blender-eye-probe.py` / `blender-render-eye.py` / `blender-eye-locate.py` 实测：
- 眼区**不是**深眼窝，而是"**雕刻的睑缘环 + 内部浅碗**"；用 cavity（空腔）着色渲染一眼可见
- **虹膜/瞳孔/睫毛全在 albedo 贴图里**（渲染 `--texture` 直接看到），所以"眼位"必须从画出来的眼球量
- 量得（女生）：**眼裂椭圆中心 (x=0.0269, z=1.0686)，半宽 9.4mm、半高 7.7mm**，
  即画出来的眼球约 **18.8 × 15.8mm**；而上一轮插的球**直径只有 14.2mm**（R=7.10mm，见交付说明）
  → 比洞口窄 4.6mm，两侧眼角必然漏空
- `eye.L` 顶点组形心 (x=0.0349) 是**眼皮皮肤**的形心，**不是眼位**（我此前误用它，把球搬偏了 ~8mm）

### 8.6.2 判定性实验：**这个眼窝在几何上不可能插球**

`tools/blender-eye-rebuild2.py`：按画出来的眼裂开孔（已删 743/777 面），取**真实拓扑边界环**，
扫描球半径 R = 9~69mm、每个 R 都用迭代法解出最优球心：

```
L 眼：最优 R=15.0mm 时 σ=1.475mm（球心距环的离散度），跨度 7.53mm，覆盖 1.012
R 眼：最优 R=16.0mm 时 σ=0.914mm，跨度 4.86mm，覆盖 1.004
判据：σ < 0.3mm 才算"睑缘环落在球面上"
```

**为什么必然失败**（可复算）：睑缘环的 **Y 跨度 12.9mm**，而能覆盖该洞口的球
（R ≥ ρ_max = 9.88mm）在同一环上**最多只能有 6.7mm 的 Y 跨度** —— 差一倍。
根因是这个眼窝**横跨脸颊的横向曲率**（PCA 拟合睑缘平面：法线相对正前方**倾斜 30°**）。
→ 插任何球都会"一侧外凸穿出眼皮、另一侧形成深坑"。**历次修复（含我上一轮的"环吸附球面"）
都栽在这条几何事实上，不是手艺问题。**

### 8.6.3 v2 的做法：把眼窝内部雕成**凸起眼球穹顶**（不开孔、不动睑缘）

`tools/blender-eye-dome.py`：
1. 用 PCA 拟合**睑缘平面的法线**（该眼窝自身倾斜 30°，必须沿它自己的法线鼓）
2. 平面内做球冠 r=16mm：`w(r) = sqrt(R²-r²) - sqrt(R²-a²)`，顶点凸起 **2.69 / 2.83mm**
3. 权重场把**内部**顶点过渡到球冠（q=1 的睑缘一圈权重 0，**完全不动**）
4. **贴图 UV 不动** → 画好的虹膜/瞳孔落在凸面上，成为真正的 3D 眼球
5. 不开孔 → 无缝隙/漏光/穿模；凸面 → 高光与体积感正常

结果：位移顶点 366/388 个（最大 5.59/6.11mm），渲染对比见
`_rig_work/dome2-front.png`（眼球微距）与 `_rig_work/dome2-face-front.png`（全脸）。

**眼神（gaze）与眨眼**：穹顶按权重场绑定到 `eye.L/eye.R` 后，转眼球骨会带动凸面**及其上的虹膜**
一起移动（贴图随几何走），gaze 仍可用；眨眼由交付规范的 `expr_blink_L/R` 形态键承担。
顺带把 `eye.L/eye.R` 的枢轴从"眼皮皮肤形心"**移到穹顶球心**（否则转眼球会把它甩出去）。

### 8.6.4 两个必须记住的环境坑

1. **本地坐标系 ≠ 世界坐标系（最坑的一个）**：原始 FBX 导入的网格带着 -90°绕X 的旋转，
   `mesh.vertices.foreach_get("co")` 拿到的是**局部坐标（Y 是身高、Z 是进深）**，
   而骨骼 `head_local` 是**世界制（Z 是身高）**。两者相差 90°：
   实测骨相骨的高斯场最近距离算成 **0.96 米**（全落到身体外）→ **权重全 0**。
   修法：**绑定前把对象变换烘进网格**（`transform_apply`），之后所有工具都能直接用 `co`。
2. **Blender 会往 C 盘写缩略图缓存**：`image.write | ERROR ... C:\Users\<用户>\.thumbnails\...`
   在只允许写工作区的沙箱下必然报错（不影响出图，但污染日志、让"到底失败没有"难判断）。
   修法：`tools/blender-env.py` 作为**第一个 `--python`** 传入，关掉 `file_preview_type`
   并把 `temporary_directory` 指到 `3D建模/_rig_work/_tmp`。

## 8.8 本轮踩到的坑（全部有实测证据，务必不要再犯）

| 坑 | 现象 | 正确做法 |
|---|---|---|
| **局部坐标 ≠ 世界坐标** | 原始 FBX 的网格带 -90°绕X 旋转，`foreach_get("co")` 拿到的是局部坐标（**Y 是身高**），而骨骼 `head_local` 是世界制（**Z 是身高**）→ 骨相骨高斯场最近距离算成 0.96 米，权重全 0 | 绑定前 `transform_apply` 把对象变换烘进网格 |

### 8.11.1 根因（**最重要的一条，别再退回布尔遮罩**）

`jaw` 20.6×、`ear.L` 13.9× 不是"场的公式写错"，而是**布尔头发遮罩制造了硬边**：

| 证据 | 数值 |
|---|---|
| 耳根处头发顶点与皮肤顶点的空间距离 | **0.30~0.72mm**（两片平行壳交替出现） |
| 该处相邻两顶点的场值 | **1.0（皮肤）与 0.0（头发）** |
| 该处相邻两顶点的实际 `jaw` 权重（下颌 +20°） | 0.35 与 0.11 → **Δw 0.24** |
| 由此产生的边长拉伸 | **20.6×**（原长 0.32mm 的边上绝对增量 8.5mm） |

机制：布尔遮罩让贴在一起的两个顶点场值相差 1.0，而权重平滑是沿**拓扑边**扩散的
（两片壳之间没有边）→ **平滑扩散不进去**，只能用 33 骨的场值硬碰硬。

修法（`tools/blender-rig-weights.py` 新增 `soft_hair_mask()`）：
把布尔遮罩沿拓扑边做 2 轮拉普拉斯扩散（α=0.5）成**连续遮罩**，
机能骨场按 `skin = 1 - soft` 软门控；骨相骨另用"hard 门"（`soft ≥ 0.6` 算头发），
避免半个头发跟着 `face_width`/`temple` 一起横向位移。

### 8.11.2 走错的一步（记录以免重走）：**"到最近头发的三维距离场"是错的**

第一版把布尔遮罩换成"到最近头发种子的三维距离 + smoothstep"。看着更"物理"，实测**灾难**：
头发只长在头上，躯干离头发 **200mm**，于是整条脖子/下巴被判成"远离头发 = 非皮肤"
→ `jaw`/`lip_upper`/`lip_lower`/`chin`/`nose` 的顶点数**全部掉到 0**（日志里一排 "⚠️ 无权重"）。
**结论：这种"排除某类材质"的门控必须沿拓扑（局部），不能用全局三维距离。**

（顺带踩到：距离变换的哨兵值 `1e6` 没截断时会顺着 `ramp` 把整张脸的场值抹成 0。
现在统一截到 `target + falloff + voxel`。）

## 8.12 【本轮·已完成】审计判据重设：**一条 1.3 卡不住"大头 + 碎屑"**

### 8.12.1 为什么必须分档

这个网格有 **36.7 万条 < 1mm 的微边**（3D 扫描重建的高密度细节）。
拉伸比 = 变形后边长 / 原边长，**在微边上会被杠杆臂放大**：
实测 `jaw +20°` 最差边**原长 0.32mm、绝对增量 4.6mm** —— 比率 15×，
而高倍渲染证明外观完全没变（§8.11.4）。上一代交付链的实测口径也是 1.89~1.99×。

### 8.12.2 新判据（写进 `tools/blender-bone-audit.py` 默认值 + 交付规范 §4.6）

| 档 | 条件 | 用途 |
|---|---|---|
| **FAIL** | 有效边（原长 > 0.3mm）拉伸 > **2.0** ／ 全边拉伸 > **6.0** ／ 微边（< 0.3mm）绝对增量 > **1.5mm** ／ 翻面面积 > **500ppm** | 硬伤，必须修 |
| **WARN（△ 观察）** | 有翻面但面积 ≤ 500ppm | 人工确认是否在不可见区域（口腔内部/头发内侧） |

## 7. 【待修】H5 里滑杆改不动模型（已定位到层级）

**现象**（可复现）：

1. 打开捏脸页 → `window.__blFaceStage` 拿到舞台（渲染器 `mountFaceStage` 已挂此句柄）
2. `window.__blFaceStage.applyCommands({ morphs: { shape_face_width_up: 1, shape_cheekbone_width_up: 1 } })`
   → `stats().warnings === 0`（说明形变键名都命中了，没有"资产里不存在"的告警）
3. **但舞台像素毫无变化**（用 `tools/crop-shot.ps1` 只裁 3D 预览区比哈希，排除滑杆数字干扰）
4. 同一时刻 `window.__blFaceStage.rotate(0.6, 0.05)`（转相机）→ **像素立刻变化**

**结论**：渲染循环是活的，适配器写入的对象**不是正在渲染的那个对象**
（`bound.getMorph()` 命中了名字、`morphTargetInfluences` 也写了，但那些 mesh 没在画面上）。

**已知的排查线索**：
- `bindThree(root)` 在 `load()` 里每次都重建（L446-448），不是"只绑一次"的陈旧问题
- 蒙皮数据完好：当前 GLB 与修复前逐项一致（skins=1、joints=20/8、7/7 图元带 `JOINTS_0`）
- 舞台统计正常：`ready=true`、`bones=20`、`meshes=7`、`materials=6`、`triangles=56077`
- **注意**：早前"眼睛分区随机 → 像素变了"的观察不可靠 —— 每次 `shot` 都会重设
  `Emulation.setDeviceMetricsOverride`（改变视口 → 触发 resize → 相机重新取景），
  那是视口变化造成的，不是滑杆生效。**判断"模型动没动"必须只比预览区像素、且固定视口。**

**下一步方向**（任选其一验证）：把 `bound` 里的 mesh 与 `root` 里真正被渲染的 mesh 做对象同一性
对比（渲染器里加一次性断言）；或确认 `GLTFLoader` 是否因缓存/两次加载产生了第二份场景。

## 5.2 导出 GLB 的两个坑（**必须照做，否则资产会悄悄变大/变坏**）

1. **`export_morph_normal` 必须关**：开启会给每个形变键写一组法线，137 个键 →
   体积从 9.6MB 涨到 **32MB**（原版资产里带法线的 morph 目标 = 0）。
2. **贴图要限到 1024**：出厂 GLB 内嵌贴图是 **1024×1024**；而 `.blend` 里常留着 2048
   （我重链男生贴图时就引入了 2048）→ 直接导出体积翻倍（女生 baked 7.2MB → 14.4MB）。
   导出脚本已加 `--texture-max 1024`（仅内存缩放，不动源文件）。

正确命令：

```powershell
blender --background <文件.blend> --python tools/blender-export-glb.py -- --out <输出.glb> --texture-max 1024
```

## 6. 踩过的坑（避免重犯）

- **测量"眼球凸出"不能用「眼球 vs 脸部最前点」**：会把鼻梁、眉弓算进来，得出正数毫无意义
  （第一版脚本错误地报告"凸出 0.026"，实为误判）。正确指标是**眼裂环到球心的距离分布**。
- **姿态判定要看四元数的 x/y/z，不能看 w**：identity 是 `[1,0,0,0]`，只看 `rotation[0]` 会把全部骨骼误报为"有残留姿态"。
- **眼区取顶点不能用"全身高度的百分比"切 Z 波段**：会取到胸腹顶点（第一版脚本的第二个误判来源）。
- Blender 无头渲染 Workbench 时，**贴图丢失的材质渲染为品红**——这反而是发现"男生贴图丢失"的快捷信号。
