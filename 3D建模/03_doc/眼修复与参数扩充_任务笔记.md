## 1. 诊断结论（已量化，可复现）

测量脚本：`tools/blender-measure-eyes.py`（无头 Blender 运行）
判定标准：**眼裂开孔那一圈边界顶点到眼球球心的距离应当 ≈ 球半径 R（且 σ 小）**
—— 小于 R 说明眼皮扎进球里（穿模），大于 R 说明有缝（眼白过多/漏光），σ 大说明眼眶形状与眼球不匹配。

| 项 | 女生 `01_female_60s_v3/_edit.blend` | 男生 `02_male_60s_v1/_edit.blend` |
|---|---|---|
| 眼球半径 R | 0.0071 | 0.0075 |
| 眼裂边界环顶点数 | 45（左）/ 38（右） | 40 / 39 |
| 环到球心 min / mean / max | **0.0072 / 0.0087 / 0.0099** | **0.0057 / 0.0092 / 0.0124** |
| σ | 0.0008 | **0.0018**（形状不匹配） |
| 判定 | 眼皮**离开球面最多 2.8mm** → 视觉上像眼球凸在外面 | 眼皮**扎进球里最多 1.8mm**（穿模）+ 形状严重不匹配 |
| 残留姿态 | ✅ 无（骨骼均单位变换） | ✅ 无 |
| 对象级缩放 / 修改器 | ✅ 无异常（仅 Armature） | ✅ 无异常 |
| 贴图 | ✅ 4 张全部已打包（源在 `E:\3D模型\常服女\`） | ❌ **4 张全部丢失**（路径指向不存在的 `3D模型\常服男\男\`）→ 渲染品红 |

**结论**：眼睛问题的根因是 **眼球与眼裂开孔「配合失配」**（不是骨骼姿态、不是残留变换、不是对象缩放）；

### 8.2 关键教训：锚点不能用"头部高度比例法"

原始网格的"头顶"含**头发体积**，比例法把整张脸算高 3~4cm
（实测算出嘴高 1.073 与眼高 1.070 齐平，明显错误）。
正确做法：**复用美术确认过的既有骨骼表**（`01_female_60s_v3/BilinAI_FaceRig_60k_edit.blend`）
——其包围盒与原始高模逐位一致（`0.6995/0.2333/1.1882`），同一坐标系，可直接当锚点：

```
neck (0,0.008,0.942) → head (0,0.005,0.998) → 头顶 1.112
jaw (0,0.012,1.062) → (0,-0.070,1.012)      chin 1.024
nose (0,-0.072,1.072) → (0,-0.087,1.049)    唇上/下 1.034 / 1.024
眉 1.093   上睑 1.086   下睑 1.056   颧骨 x=0.040 z=1.052   耳 (0.052,0.016,1.072)
★ 原眼位（掏空前 eye.L/R 顶点组形心）= (±0.0349, -0.0584, 1.0701)
  既有骨骼表里写的是 (±0.0239, -0.0549, 1.0712) —— 那是**上一轮放错 1cm 的球位**，不要用
```

## 7. 【待修】H5 里滑杆改不动模型（已定位到层级）

**现象**（可复现）：

1. 打开捏脸页 → `window.__blFaceStage` 拿到舞台（渲染器 `mountFaceStage` 已挂此句柄）
2. `window.__blFaceStage.applyCommands({ morphs: { shape_face_width_up: 1, shape_cheekbone_width_up: 1 } })`
   → `stats().warnings === 0`（说明形变键名都命中了，没有"资产里不存在"的告警）
3. **但舞台像素毫无变化**（用 `tools/crop-shot.ps1` 只裁 3D 预览区比哈希，排除滑杆数字干扰）
4. 同一时刻 `window.__blFaceStage.rotate(0.6, 0.05)`（转相机）→ **像素立刻变化**

**结论**：渲染循环是活的，适配器写入的对象**不是正在渲染的那个对象**
（`bound.getMorph()` 命中了名字、`morphTargetInfluences` 也写了，但那些 mesh 没在画面上）。

**已知的排查线索**：
- `bindThree(root)` 在 `load()` 里每次都重建（L446-448），不是"只绑一次"的陈旧问题
- 蒙皮数据完好：当前 GLB 与修复前逐项一致（skins=1、joints=20/8、7/7 图元带 `JOINTS_0`）
- 舞台统计正常：`ready=true`、`bones=20`、`meshes=7`、`materials=6`、`triangles=56077`
- **注意**：早前"眼睛分区随机 → 像素变了"的观察不可靠 —— 每次 `shot` 都会重设
  `Emulation.setDeviceMetricsOverride`（改变视口 → 触发 resize → 相机重新取景），
  那是视口变化造成的，不是滑杆生效。**判断"模型动没动"必须只比预览区像素、且固定视口。**

**下一步方向**（任选其一验证）：把 `bound` 里的 mesh 与 `root` 里真正被渲染的 mesh 做对象同一性

```powershell
blender --background <文件.blend> --python tools/blender-export-glb.py -- --out <输出.glb> --texture-max 1024
```

## 6. 踩过的坑（避免重犯）

- **测量"眼球凸出"不能用「眼球 vs 脸部最前点」**：会把鼻梁、眉弓算进来，得出正数毫无意义
  （第一版脚本错误地报告"凸出 0.026"，实为误判）。正确指标是**眼裂环到球心的距离分布**。
- **姿态判定要看四元数的 x/y/z，不能看 w**：identity 是 `[1,0,0,0]`，只看 `rotation[0]` 会把全部骨骼误报为"有残留姿态"。
- **眼区取顶点不能用"全身高度的百分比"切 Z 波段**：会取到胸腹顶点（第一版脚本的第二个误判来源）。
- Blender 无头渲染 Workbench 时，**贴图丢失的材质渲染为品红**——这反而是发现"男生贴图丢失"的快捷信号。
