# ⚠️ 重要发现：`3D建模/女医` 里的资产**不是女医**（2026-10-05）

> 用户反馈：「点击视频通话进入 3D 模式后显示的是男生 Q 版形象，**企鹅服装**的那个，
> 但是男医资产应该是身穿白大褂的形象」。
> 排查结论：**用户看到的确实是"企鹅"形象，原因是通话页默认加载「女」那份，
> 而 `3D建模/女医` 里的 OBJ 网格其实是企鹅玩偶**。男医那份是**正确的白大褂医生**。

---

## 1. 证据链（都是客观量，不是肉眼判断）

### 1.1 资产内部指纹与源文件一致 → 不是管线搞混

| 文件 | 顶点数 | 形态键 |
|---|---|---|
| `source_male3_zup.blend` | 749,934 | 0 |
| `female3_delivery.blend` | **29,495** | 23 |
| `male3_delivery.blend` | 29,490 | 23 |

两份交付件都**忠实来自各自的源文件**（709k 级降到 29k 级、面数 58,998/59,000），
4 张 4096² 贴图名与路径都在。所以问题在**源文件本身**，不在减面/绑骨/导出。

### 1.2 几何分布指纹比对 → 女医 OBJ 实为企鹅

把顶点归一到单位包围盒，切成 6×10×6 格做占比直方图，两两算余弦相似度：

| 比对 | 余弦相似度 | 判定 |
|---|---|---|
| 男医 vs 女医 | 0.8862 | 不同角色 |
| 男医 vs 企鹅（`E:\download\模型男2`） | 0.8637 | 不同角色 |
| **女医 vs 企鹅** | **0.9679** | **高度相似** ← |

即 `3D建模/女医/Q版女医/ba9ff1c7….obj`（749,956 顶点 / 149.99 万面）
**在形体上就是企鹅玩偶**，只是面数是企鹅资产（249,996 顶点）的 3 倍。

### 1.3 渲染互证

- `male3_delivery.blend` 渲染 → **白大褂 + 听诊器的男医** ✅（与用户预期一致）
- `female3_delivery.blend` 渲染 → **企鹅身体 + 医生脸**（网格是企鹅、贴图带医生面部细节）

## 2. 为什么用户"进 3D 模式看到企鹅"

两个原因叠加：

1. **通话页默认加载「女」**（`DEFAULT_GENDER = 'female'`）→ 一进去就是女那份 = 企鹅；
2. **浏览器缓存**：资产是**同名替换**（`BilinAI_FemaleFaceRig_60k_delivery_baked.glb`），
   URL 没变，浏览器继续用旧副本 —— 改了等于没改。

---

## 3. 本轮的修法

| 改动 | 说明 |
|---|---|
| `DEFAULT_GENDER` 改为 **`'male'`** | 用户要的是白大褂男医；进 3D 模式直接看到正确形象 |
| 新增 `ASSET_VERSION` + `resolveAssetUrl` 对 `.glb` 追加 `?v=` | **破缓存**。以后**每次重新导出资产都要把版本号加一**，否则又一次"改了等于没改" |

验证（无头 Edge 读 `window.__blFaceStage.stats()`）：
```

```

## 5. 排查手法留档（以后资产"看起来不对"可复用）

1. **几何分布指纹 + 余弦相似度**（`_rig_work/_probe_fingerprint.py`）
   —— 贴图是图集噪声、渲染又可能互相矛盾时，**几何分布是唯一可靠的仲裁**；
2. **逐文件探针**（`_rig_work/_probe_asset.py`）：打印每个中间产物的顶点数/面数/材质/贴图名，
   一眼看出"哪一步开始变了"；
3. **同名替换资产必须破缓存**，否则端侧看到的仍是旧模型（本轮踩到）。
