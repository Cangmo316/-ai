## 1. 变更后的产品范围

| 能力 | 变更前 | 变更后 |
|---|---|---|
| **3D 捏脸** | 捏脸页 10 分区 / 99 条滑杆，`shape_*` 113 个形态键，两套参数表 | ❌ **移除**（连带移除滑杆 UI、参数表、`test-face-params` 的覆盖率判据） |
| **唇形同步** | `vis_* 15` + `expr_* 8`（含眨眼/微笑） | ✅ **保留并强化**（这是核心） |

## 2. 新模型实勘结果（已实测）

来源：`E:\download\模型男2\0d68b8aa72780b85ce5e72d19b9fd22b.obj`

| 项 | 实测值 |
|---|---|
| 网格 | 249,996 顶点 / 500,000 三角面（**已是减过面的版本**，原版应是 100 万级） |
| 材质/贴图 | 1 材质 + **4 张 4096² PBR 贴图齐全**（albedo/normal/metallic/roughness，MTL 为空壳） |
| UV | 有（`UVMap`） |
| 骨骼/权重/形态键 | **全无** → 需要从头绑 |
| 轴向 | 已是 **Z-up**、脸朝 **−Y**（与既有管线一致，**无需转轴**） |
| 包围盒 | x[−0.404, 0.409] y[−0.218, 0.263] z[0, 1.116]；**身高 1.1162m** |
| 头部 | 面高约 **0.1488m**，头顶 z=1.1162，下巴 z≈0.967 |
| 面部 landmark | 眉 z≈1.067 / 眼 z≈1.049 / 鼻 z≈1.033 / 嘴 z≈1.005 / 下巴 z≈0.973 |
| 体型 | **肩宽 0.813m（很宽）**，比例与既有 60k 资产完全不同 |

**美术风格（这是最关键的一点）**：渲染实测是**卡通风格的小男孩玩偶**——
圆胖身体、连体熊装（帽子耳朵与身体连成一体）、腮红、**浅眼窝的大眼睛**、
**已经是微笑的嘴**（嘴角上扬）。**不是写实角色**，与之前给老人做的写实/半写实女性资产是两套语言。

**姿态**：**不是 T-pose**（手臂略外张、腿部短粗）→ 手臂骨骼要按**这个姿态**去量，
不能照搬 T-pose 的做法。

**其他要留意的**：
- 手指与脚部是**圆团造型**（没有独立手指）→ "招手"只能做**整条手臂 + 圆团手**的摆动，
  做不了手指动作（这对"招手"足够，但方案里别写"挥手打招呼"以外的手势）；
- 衣服/帽子与身体**同一网格**（不像旧男生那样有独立服装）→ **不可换装**；
- 眼睛是画在贴图上的浅眼窝（见 `_rig_work/m2-body-front.png`），
  **可能不需要**女生那套"独立眼球 + 布尔挖眼裂"（那套是为写实扫描的深眼窝做的）。

## 3. 管线要改哪些（对照现有工具）

| 环节 | 现有工具 | 变更后 |
|---|---|---|
| 减面 | `blender-decimate.py`（目标 59,300） | 目标待定：**不含捏脸可不必 60k 上限**，但要为端侧性能定新预算（见决策点 3） |
| 骨架 | `blender-rig-structural.py`（33 骨，聚焦面部） | **需大改**：新增**肩/上臂/前臂/手**骨骼链（招手），面部只保留嘴/下颌/眼球 |
| 权重 | `blender-rig-weights.py`（解析场 + 头发遮罩） | 需扩展到手/臂；头发遮罩口径对这个模型要重标 |
| 口型 | `blender-morph-build.py`（`vis_* 15`） | **保留**，但要在这个模型的嘴型上重标（现在是"已微笑"的嘴） |
| 捏脸 | `blender-morph-shape-build.py`（113 个 `shape_*`） | ❌ **下线** |
| 口内 | `blender-mouth.py`（口内几何） | 待定：卡通嘴是否需要口腔内壁（见决策点 2） |
| 减骨 | `blender-reduce-bones.py`（→7 骨） | **要重设**：7 骨里没有手臂 → 需扩到包含手臂与手的骨（见决策点 3） |
| 导出 | `blender-export-glb.py` | **新增**：导出**动画**（招手）。现在导出的是"不导出动画" |
| 判据 | `test-avatar-v2-glb.mjs`（`shape_* 113` 契约） | **要改契约**：不再要求 `shape_*`；改判 `vis_*`/`expr_*` + **动画片段存在** |

**特别提醒（工程现实）**：现有导出脚本明确**不导出动画**（`--keep-morph-prefix` 那套只管形态键）。
"招手"要么做成：
- ① **骨骼动画片段**（glTF animation）随 GLB 导出，端侧 three.js 播放；
- ② 或做成**形态键**（不推荐：手臂摆动用 morph 体积大且难复用）；
- ③ 或端侧用代码**程序化驱动骨骼**（不需要动画数据，最简单、最省体积，但美术调不了曲线）。
→ 见决策点 4。

## 4. 需要你拍板的 4 件事

1. **捏脸页怎么处理**：整页移除 / 保留页面但去掉 3D 预览 / 保留但只读？
   （影响 `pages/face/face.vue`、参数表、两套测试）
2. **口型用哪条路**：
   - A. **形态键**（沿用现有 `vis_*` 15 组，保留文字级对齐驱动）——口型可控、可复用现有代码；
   - B. **只转下颌骨**（最省，但卡通嘴的表情表现力弱）；
   - C. **形态键 + 下颌骨**（推荐，表现力最好，工作量中等）。
   同时决定：**是否保留眨眼/微笑等表情**（现在是"已经微笑"的卡通嘴）。
3. **资产范围**：只做这个新男生 / **男生 + 女生都重做**（女生现在是另一套写实资产，
   若只留口型+招手，女生那 113 个 `shape_*` 与眼球手术是否也一并下线？）
4. **"招手"的实现形态**：端侧程序化驱动骨骼（最省）/ 烘焙动画片段随 GLB 导出（美术可控）/
   形态键（不推荐）。

## 5. 我的建议（等你确认后开工）

- **决策 1**：整页移除（既然不做捏脸，保留一个空壳页面只会增加维护面与合规面）；
- **决策 2**：选 **C（形态键 + 下颌骨）**，口型保真度对"陪伴老人"这个场景很重要；
  保留**眨眼**（卡通脸很吃眨眼），微笑可以不做（模型本身就是笑的）；
- **决策 3**：**先只做新男生**（你给的就是他），跑通后再决定女生是否统一风格——
  两个角色风格不一致（写实 vs 卡通）本身就是产品决策；
- **决策 4**：**烘焙动画片段**（美术能调曲线、端侧只播）；同时预留程序化驱动的接口。
